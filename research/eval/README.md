# Run 1 evaluation (complete time signatures)

For the layout1 piano benchmark, the visual audit links the actual scan and rendered page for each of 29 pieces. It gives per-bar pitch matches, whole-piece F1 with either staff accepted, and the released-model repetition on Hungarian Rhapsody No. 6. [Scan/render audit](scan_render_audit.md)

When an edition, its reference XML and its render disagree, record the affected measure and which source supports the correction. The first open octave-span checks are *Winter Wind* m. 20 and Schubert D. 899 No. 4 m. 64. [Render and reference XML corrections](scan_render_audit.md#render-and-reference-xml-corrections)

Frozen pipeline, identical for every model (566, control, run1).

1. Pages: `pdftoppm -r 150 -png [-f 3 -l 16 for Mazeppa] <score.pdf> pages/<folder>/page`
   (150 dpi, as `run/pipeline.py`; PDFs from the SCORES map of `out/compare/index.html`).
   The La Campanella pages are byte-identical to the earlier `work/` renders.
2. Recognition, one call per piece with all pages (symlinks to `pages/<folder>/`), cwd and
   PYTHONPATH = the code copy, fixed staff cutting (`HOMR_FIXED_MARGIN=1`, upstream's cutting,
   as "ours-fixedcut" and upstream566 in PROGRESS.md), default options otherwise:
   `run_model.sh <model> <worktree>` calls
   `PYTHONPATH=$WT HOMR_FIXED_MARGIN=1 python run_homr.py <model>/<folder>/page-xml <model>/<folder>/pages/page-*.png`
   (`run_homr.py` = `homr.main` plus a copy of the per-page MusicXML before relieur joins and deletes them).
   Code copies: 566 = `run/octave_wt` (octave-on-566, model 566 ONNX, unmodified);
   run1 = `run/meter_wt` (meter-run1 at 10bc7e6; uncommitted edit of `homr/transformer/configs.py`
   `model_name = "meter_run1"`; fp32 ONNX from vast-homr4:/workspace/onnx/meter_run1/);
   control = `run/control_wt` (worktree of octave_wt HEAD = 566 code; uncommitted `model_name = "meter_control"`; fp32 ONNX from vast-homr4:/workspace/onnx/meter_control/).
   Segnet and staff-relation ONNX files copied from octave_wt. CPU transformer (fp32), Apple M4.
3. Join and score, `join_score.sh <model> <folder>`:
   `HOMR_PAGES=<model>/<folder>/page-xml HOMR_OUT=<model>/<folder>/joined python run/merge_pages.py`
   `python run/drop_minor_parts.py joined.musicxml <folder>-<model>.musicxml`
   `cd run/octave_wt && python -m validation.score_notes run/out/compare/<folder>/<folder>-reference.musicxml <model>=<folder>-<model>.musicxml --json <model>/<folder>/note-scores.json`
4. `python meter_eval.py` writes `results.json` and `summary.md` (definitions in its docstring).

Check: the 566 per-note scores (pitch+onset+duration F1) equal the earlier
`note-scores*.json` upstream566 entries for all eight pieces (e.g. Mazeppa 34.84, La Campanella 67.96).

## Run 2 additions (printed accidentals, key signatures)

New files; `meter_eval.py` and all reference files are unchanged.

- `make_printed_refs.py` writes `run/out/compare/<folder>/<folder>-reference-printed.musicxml` for the five
  KernScores-based pieces (all five test PDFs are LilyPond engravings: Bach prelude/fugue 2.9.10,
  K. 331 unversioned, K. 309 2.10.33, Op. 13 2.12.2; Rachmaninoff Op. 3 No. 2 is 2.18.2, La Campanella
  MuseScore 2.3.2, Mazeppa a scan of a Soviet edition via ABCpdf). Step 1: `<accidental>` from
  `homr/accidentals.py` `AccidentalState.printed_sign` (branch accidentals-run2, `run/acc_wt`) per staff,
  step+octave carry, ties across barlines, key from `<fifths>`, plus the LilyPond natural-sharp /
  natural-flat when a double sign is reduced to a single one (written as `natural-sharp`; the scorer folds
  it to `#` as the vocabulary does) and a repeated sign on a note tied over a system break (prelude and
  fugue only; bar labels there equal the measure index). Step 2: hand corrections in
  `printed/<folder>.corrections.json` (each with a reason) from comparing the PDF page images.
  Fugue only: courtesy repeats of a carried double sign (more than 1 quarter after the last printed one, or in
  another voice) are generated by a rule that fits about 85% of the bars checked; wrong cases are corrected.
  `printed/*.stats.json` count rule signs, corrections and differences to music21's signs.
  The references are verified only on the pages listed in the report (prelude, K. 331: all pages; fugue
  m1-35; K. 309 m1-31; Op. 13 m1-5, m20-27); other bars hold the rule output only.
- `key_eval.py` -> `key_results.json`, `key_summary.md` (definitions in its docstring).
- `accidental_eval.py [--models 566 run1 ...]` -> `accidental_results.json`, `accidental_summary.md`.
  Works on any model's joined output in the same layout. Baseline: 566 and run1 (nearly no `<accidental>`).
